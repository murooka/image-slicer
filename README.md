# Image Slicer

縦長の画像を、色が切り替わる位置で自動的に分割するブラウザツールです。
処理はすべてブラウザ内（Web Worker）で行い、画像はどこにもアップロードされません。

## 使い方

1. 画像をドロップ（またはクリックして選択）する
2. 最小高さ・最大高さ・最大分割枚数を指定する（プレビュー上の分割線がすぐに更新されます）
3. 意図しない位置で切れている場合は、プレビューで調整する
   - 分割線をクリックすると、その付近（既定 ±40px）では切らなくなり、別の位置が選び直される
   - 画像上を上下にドラッグすると、その範囲では切らなくなる
   - 斜線の範囲をクリックすると解除できる。ほかに条件を満たす位置がない場合だけ、範囲内で切ってオレンジの破線で示す
   - 分割線をドラッグすると移動、× で削除、画像をダブルクリックすると追加できる。これらの操作を行うと「手動編集」モードになり、分割条件を無視して
     人が置いた位置で切る（条件を満たさない区間は警告するが、そのまま書き出せる）。
     「元に戻す」（Ctrl/⌘ + Z）で 1 操作ずつ戻せ、最初まで戻すか「自動分割に戻す」で自動モードに戻る
4. 「スライスを書き出す」を押し、ZIP または個別にダウンロードする
5. 画像の配置先 URL を入れておくと、分割した画像を順に並べる `<img>` タグを出力します

## PWA

一度開くとすべてのファイルが Service Worker にキャッシュされ、オフラインでも使えます。
Chrome / Edge ではアドレスバーのインストールボタン、iOS Safari では「ホーム画面に追加」でアプリとしてインストールできます。

新しいバージョンを公開すると、次に開いたときに「新しいバージョンがあります」と表示されます。
編集中の分割線が失われないよう、自動では再読み込みせず、「更新する」を押したときに切り替わります。

アイコンは `public/icon.svg` が元データです。PNG（`public/pwa-*.png` など）はこの SVG から書き出しています。

## 分割ロジック

1. 画像を 256 行ずつ読み出し、行ごとに次の特徴量を計算する（巨大な画像でも 1 枚の canvas に載せない）
   - 量子化した色ヒストグラム（累積和として保持）
   - 直上の行から色が大きく変わった画素の割合
   - 行内で隣の画素から色が大きく変わる割合（文字や写真の有無）
2. 行ごとのスコアを計算する: `色分布の差 × wBand + 境界線 × wEdge + 行の均一さ × wFlat`
   - 色分布の差: 分割位置の上下の帯（既定 24px）の色ヒストグラムの差。セクションの境界で高くなる
   - 境界線: 直上の行から色が大きく変わった画素の割合
   - 行の均一さ: 分割位置を挟む 2 行に文字や写真が少ないほど高い。wFlat を 0 にすると色の変化だけで判定する
3. 最も高い区間から順に、上下とも最小高さを保てる範囲でスコア最大の位置で 2 分割する。
   同点なら区間の中央に近い位置を選ぶ
4. すべての区間が最大高さ以下になったら終了する

最大分割枚数を守るため、各区間に最低限必要な枚数 `ceil(高さ / 最大高さ)` の合計が上限を超えない位置だけを分割候補にします。
最大高さは最小高さの 2 倍以上である必要があります。

## 開発

パッケージ管理には pnpm を使います（バージョンは `package.json` の `packageManager` で固定）。

```sh
pnpm install
pnpm dev     # 開発サーバー
pnpm test    # 単体テスト
pnpm build   # dist/ に出力
```

## デプロイ

`main` に push すると GitHub Actions（`.github/workflows/deploy.yml`）がテスト・ビルドして GitHub Pages に公開します。
初回のみ、リポジトリの Settings → Pages → Build and deployment → Source を「GitHub Actions」に設定してください。
